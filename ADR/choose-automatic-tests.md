**ADR: choose-automatic-tests - выбор автоматических тестов**

**Дата:** 18 ноября 2026 г.

**Статус:** Принято

**Контекст:**

Для системы бронирования отелей необходимо определить единый подход к тестированию работы проекта, который обеспечит маскимальное покрытие тестами проект, при этом был легок на написание и чтение кода. Необходимо учесть:

1. Простота работы с тестами.
2. Совместимость с сервисами.
3. Удобство.
4. Понятные ошибки при выводе неверных данных.

**Backend**

**Рассмотренные варианты:**

1. **Vitest:** Создан для проверки сервисов, бизнес-логики, функций на NestJS.
2. **MSW:** Библиотека для перехвата сетевых запросов и подмены ответов API в браузере и Node.js
3. **Faker:** Библиотека для генерации тестовых данных. Создание пользователей, отелей, номеров и бронирований.
4. **Supertest:** Библиотека для автоматического интеграционного и сквозного (E2E) тестирования HTTP-эндпоинтов.
5. **Гибридный подход:** Использование нескольких технологий вместе для полного покрытия тестов, каждая библиотека выполняет свои прямые тестовые варианты.

**Решение:**

Выбран Гибридный подход.

**Обоснование:**

- **Удобство** - у каждой библиотеки свой функционал, рассчитанный на определенный вид теста, максимально используется весь функционал
- **Большое покрытие** - в связке многих библиотек покрывается большой процент кода

**Недостатки решения:**

- **В каждой библиотеке нужно разбираться** - каждый разработчик должен понимать как и для чего используется отпределенная библиотека
- **Многословность (Boilerplate)** - нужно для каждой библиотеки писать много legacy code

**Последствия:**

- Необходимо обеспечить обучение команды (если требуется) для эффективной работы с библиотеками.

**Frontend**

**Рассмотренные варианты:**

1. **Vitest:** Создан для проверки функций, hooks и утилит.
2. **React Testing Library:** Библиотека для проверки React-компонентов и пользовательских действий.
3. **Playwright:** Библиотека для проверки пользовательских сценариев в браузере.
4. **MSW:** Библиотека для перехвата сетевых запросов и подмены ответов API в браузере и Node.js.
5. **Гибридный подход:** Использование нескольких технологий вместе для полного покрытия тестов, каждая библиотека выполняет свои прямые тестовые варианты.
